# reTerminal E1004 SD 卡图片新旧抖动算法对比（DitherCompare）

在 13.3 英寸 6 色电子墨水屏（1200×1600，T133A01，竖屏）上，把**同一张图片**分别用新库（Seeed_GFX2 `dither/Dither.h`）和旧库算法（原 Seeed_GFX 的 Floyd-Steinberg 副本）渲染并屏显对比，新库一侧支持**全部参数串口实时调参**，是 E1002 同名示例的 E1004 移植版。

## 显示布局（竖屏：上下分屏）

E1002 版是左右分屏，但 E1004 是竖屏——左右分屏时每半只有 599×1600（0.37:1），普通照片会被压得无法辨认。因此本示例改为**上下分屏**：

| 区域 | 行范围 | 内容 |
|---|---|---|
| 上半屏 | 0–798 | **新库**渲染结果（受串口参数控制） |
| 分隔线 | 799–800 | 2 像素黑线 |
| 下半屏 | 801–1599 | **旧库**渲染结果（固定基线，公平对比用） |

每个半屏是 1200×799（约 3:2），横版照片基本不变形。两侧抖动的都是**同一张完整的半屏源图**，而不是把一张大图裁成两半，保证对比公平。

三种显示模式（串口命令）：

- `c` —— 上下分屏对比（默认）
- `a` —— 全屏新库：1200×799 画面垂直居中（y=400），上下留白
- `b` —— 全屏旧库：同样布局

> 全屏模式不做 1600 行放大——那需要额外 5.76 MB RGB 缓冲，超出内存预算（见下）。

## 内存策略（8 MB PSRAM）

E1002 的做法（全尺寸存图 + 副本 + 缩放 + 双索引缓冲 + 合并 + 打包）在 1200×1600 上需要约 12 MB，放不下。本示例的策略：

1. **源图按半屏尺寸存储**：解码后立即缩放到 1200×799（RGB 2.87 MB），不存全尺寸副本。
2. **合并缓冲直接做成打包 4bpp**：960 KB（不是 1 字节/像素的 1.92 MB）。
3. **两个半屏顺序抖动**：旧库半屏用 1 字节/像素索引缓冲（936 KB），拷入合并缓冲后立即释放；新库半屏用 `dither_image_4bpp` 直出打包 4bpp（468 KB）。
4. 峰值额外占用约 **4.8 MB**（另有 960 KB 显示帧缓冲），8 MB PSRAM 足够。**务必在开发板菜单中启用 OPI PSRAM**。

## 各参数作用说明（Parameter Effect Summary）

| 参数 Parameter | 作用 Effect | 何时调大 When to increase | 何时调小 When to decrease |
|------|------|------------|------------|
| **Gamma** 伽马 | 整体亮度曲线 | 画面偏暗看不清细节 | 画面过曝/发白 |
| **Saturation** 饱和度 | 颜色鲜艳程度 | 色彩暗淡不鲜艳 | 颜色溢出/出现色块 |
| **Darkness** 暗度 | 抖动前预压暗 | 电子纸显示偏亮发灰 | 暗部死黑无细节 |
| **Contrast** 对比度 | 明暗层次分离 | 画面灰蒙蒙层次不清 | 高光过曝/暗部死黑 |
| **Diffusion** 扩散强度 | 误差传播比例 | 需要平滑渐变过渡 | 想要干净少噪点 |
| **Warmth** 色温 | 红蓝通道平衡 | 强调暖色调（落日等） | 强调冷色调（水面/蓝天） |
| **Clamp** 钳位 | 误差缓冲范围 | 纯色色块边缘更干净（`l` 开） | 照片渐变过渡更自然（`l` 关） |
| **Serpentine** 蛇形 | 之字形扫描 | 减少线条伪影 | 几何图案（`p` 关） |

## SD 卡准备

1. SD 卡格式化为 FAT32，创建 `/img/` 目录并放入图片（JPG/BMP/PNG，按魔数识别格式）。
2. 默认读取 `/img/demo.jpg`；找不到时自动扫描 `/img/` 和根目录，取第一个支持的图片。
3. 建议用**横版约 3:2 比例**的图片，与 1200×799 半屏画幅最接近。

## 自定义调色板

默认使用理论 sRGB 参考值。按 `k` 打开自定义调色板后可用 `k1 R G B` 等命令现场改色；也可以直接编辑代码顶部的 `CUSTOM_PALETTE` 数组，填入你自己面板的实测值（配合色度计或手机取色）。库内置 E6 调色板已是校准值，只有你面板的实测值才值得覆盖。
